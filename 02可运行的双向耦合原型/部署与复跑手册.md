# 部署与复跑手册

运行入口位于 `02可运行的双向耦合原型/`。请完整复制 submission 目录，并保持 02 与 04 目录相邻；运行所需 Python、OpenFOAM、preCICE、适配器和绘图库均已封装在随附镜像中。

## 1 环境准备

- 推荐 Windows 10/11 x86-64 的 Docker Desktop（启用 WSL2/Linux 容器），或 Linux x86-64 的 Docker Engine。
- 启动 Docker，确认 `docker info` 正常返回服务端信息。Docker 本身需由接收方安装。
- 建议至少 4 核 CPU、8 GB 内存、10 GB 可用磁盘空间；细网格或完整研究应增加资源和等待时间。
- 接收方无需安装主机 Python、OpenFOAM、preCICE、Git 或编译器。已安装 Docker 后，导入和算例运行可以离线完成。
- 随附镜像平台为 `linux/amd64`。ARM 设备需 Docker 支持 amd64 模拟，性能和稳定性不属于本次推荐平台范围。
- 将整个提交包解压到普通本地目录，避免逗号出现在目录名中；路径可包含中文和空格。Windows 如提示共享目录权限，允许 Docker 访问工程目录。

## 2 Windows 启动

在 `02可运行的双向耦合原型/` 打开 PowerShell：

```powershell
# 默认演示阀门控制、双向背压与温度/相分数输运
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1

# 正式算例 A：稳态 Poiseuille 水力
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -Case steady

# 正式算例 B：无源项温度与相分数输运
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -Case advection

# 联合加密配置
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -Case refined
```

首次运行自动校验 `images/cfd-coupling-submission.tar.gz`，导入镜像并核对镜像 ID。已有相同镜像时直接启动，不依赖从网络重新下载软件包。脚本中的 ExecutionPolicy 仅对该 PowerShell 进程生效。

每次自动产生独立输出目录，也可显式指定 `-OutputName my-valve-01`；已有目录不会覆盖。使用自定义输入时，例如 `-Case cases/transport-advection-time-refined.json`。

## 3 Linux 启动

在同一工程目录执行：

```bash
bash run.sh --case valve
bash run.sh --case steady
bash run.sh --case advection
bash run.sh --case refined --output-name my-refined-01
```

脚本使用当前用户的 UID/GID 写入输出文件。当前用户须有权访问 Docker 引擎和工程目录；如系统通过 Docker 用户组授权，按 Docker 官方安装说明配置后重新登录。

## 4 输出及运行状态

Windows 的 `run.ps1` 默认在同一终端显示求解日志与实时参数，无需另开监控终端。稳态、输运、阀门算例以及批量试验均显示仿真时间、质量流量 mdot（kg/s）、背压 p（Pa）、温度 T（K）、相 A 体积分数 alpha、阀门开度和已接受窗口数；批量试验自动跟随各子工况。状态通常约每 0.5 秒读取一次，以有更新的接受窗口为准。稳态算例为等温单相模型，T=300 K、alpha=1 为固定状态值。

控制台显示输出路径和最终收敛窗口数。实际结果保存在 `04可复现材料包/results/<本次运行名>/`，包括：

| 文件 | 内容 |
| --- | --- |
| `status.json` | 最新接受窗口、关键变量和运行状态 |
| `pipe.csv`、`control_events.csv` | 一维轨迹和阀门控制时刻 |
| `foam_accepted.csv`、`fluid3d/` | 三维接受轨迹和场文件 |
| `summary.json`、`transport_summary.json` | 误差、守恒与双向延迟统计 |
| `window_balances.csv`、`traces/` | 窗口账本和原始记录 |
| `report.md`、PNG 图 | 算例分析输出 |
| `pipe.log`、`foam.log`、`container.log`（如由主机脚本运行） | 进程日志 |
| `accepted_windows.jsonl`、`process_cleanup.json` | 接受窗口与子进程退出记录 |
| `case.json`、`source_snapshot/`、环境 JSON | 实际配置、源代码及环境追溯 |

`run.ps1` 或 `run.sh` 正常返回 0 且显示 `Completed and checked` 表示求解和内置结果检查均完成。失败时保留输出目录，先查看 `status.json`、`pipe.log` 和 `foam.log`。不要将“已出现结果文件”等同于完整运行成功。

实时监控由工程 `scripts/run_video.ps1` 统一实现；独立读取状态时也可使用 `scripts/watch_status.py`。Docker 启动入口使用 `/work` 的容器内相对结构，不依赖交付前电脑的绝对路径。

## 5 自动研究及测试入口

```powershell
# Windows：全部模型测试，或完整基础研究 / 技术补强研究
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -Tests
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -Study validation
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -Study hardening
```

```bash
# Linux
bash run.sh --tests
bash run.sh --study validation
bash run.sh --study hardening
```

完整研究会顺序运行多个算例，耗时明显长于单算例。`hardening` 研究包含两次故意终止参与者的故障注入；研究执行清单会按预设条件判断其结果。普通 `--case` 运行不会注入故障。接受日志用于诊断，当前恢复方式是从原始输入重新运行。

## 6 对照报告与复现容差

`04可复现材料包/` 内已有三组数值试验数据目录：`results/verification/`、`results/exploratory-study/`、`results/hardening-study/`。它们保留报告的原始输入、原始数据、图表、日志、环境记录和逐次源码快照。新的运行目录与这些记录并存。

设计与结果以两份 Word 为准，使用宋体、Times New Roman、原生公式及图表。报告数据和图表可在 `04可复现材料包/results/` 中查找。Word 的技术补强结果对应 `results/hardening-study/metrics.json`。

同镜像、同输入比较时，稳态速度和压力相对差建议不超过 0.1%；最大温度场 RMS 差建议不超过原值的 5% 或 0.001 K（取较宽者）；相分数 RMS 差不超过 5% 或 0.00003（取较宽者）。控制事件数量、接受窗口数量与物理终止时刻应一致，仍须通过脚本自带数值检查。

墙钟时间和延迟受 CPU、Docker 配置及系统负载影响，不要求跨机器逐值一致。便携入口的 `execution.json` 计时从已进入容器后开始，排除镜像导入和外层容器启动；报告计时口径以对应记录为准。

## 7 环境锁定、版本与源码构建

以下源码、环境与构建文件均位于 `04可复现材料包/`。

`environment/runtime.json` 记录镜像标签、固定 ID、平台和镜像归档 SHA-256；`environment/solver-environment.json` 保存 Python、编译器、pip 和系统软件包版本。运行环境为 OpenFOAM 2512、preCICE 3.4.1、Python 3.12.3 和 GCC 13.3，Python 绑定 pyprecice 3.4.0。

`VERSION.json`、工程 `.git` 提供本次提交快照的版本信息。运行源码快照用于结果追溯。`FILE_SHA256.json` 覆盖交付工程中除 Git 内部元数据以外的文件，可用于传输完整性检查。

如需修改求解器并从源码重新构建，保留的 `containers/`、`scripts/prepare.py`、`scripts/build.py`、`requirements.txt` 和固定提交的上游 ZIP 可用于构建：在安装 Python 3.12 后运行 `python scripts/build.py`。完整源码构建需要网络访问 Ubuntu/OpenFOAM 软件源及 preCICE 官方发布站点，后续软件源变化可能影响重新解析的系统依赖；直接导入随附镜像可保持本次固定的二进制环境。

上游资料、版本与许可证见 `THIRD_PARTY.md` 及 `third_party/`。OpenFOAM 开发包和已修改适配器的源码也保留在镜像中。

## 8 常见问题

- Docker 无法连接：先启动 Docker Desktop/Linux 引擎，再执行 `docker info`。
- 镜像 SHA-256 不一致：重新完整复制镜像文件，不跳过校验。
- 输出目录已存在：换一个 `OutputName`，保留既有原始结果。
- 主机资源不足或容器超时：增加 Docker 内存/CPU 分配，先运行基础算例，再运行细化研究。
- 源码构建下载失败：检查外网访问和证书配置；已有随附镜像时可直接按第 2、3 节运行。
